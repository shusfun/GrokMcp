Grok Supervisor：无头执行与 TUI 动态切换

Codex 负责理解、拆分、审批和验收；Grok 负责重型调查与实施；Wails 提供任务总览、托盘、恢复与按需 TUI。

设计日期 2026-09-17 默认无头 同一持久 Session Windows x64 macOS Intel / Apple Silicon
01

产品目标

用户监督 Codex用户只面对一个主控 Agent，不跟踪 Grok 中间过程。
Codex 负责编排生成任务契约、拆分工作、审批 Plan、验收结果。
Grok 承担重活代码调查、实现、测试、修复和多轮返工。
Wails 提供控制面显示任务阶段、原生托盘、恢复和 TUI 切换。
不在 React 中重绘 Grok TUI，不转发完整思考流，不为每个 turn 新建 session，不随应用捆绑 Grok Build。

03

无头执行与 TUI 动态切换

Headless · 默认

  • Supervisor 通过 ACP 驱动 Grok。
  • 不打开终端窗口。
  • Wails 只显示阶段、最近动作和边界状态。
  • Codex 阻塞等待，不接收过程日志。

Headed · 按需

  • 系统终端运行 grok --resume <session_id>。
  • 显示原生思考、命令、编辑、测试和权限 UI。
  • 用户可直接输入、取消或继续。
  • 多个 TUI 可分布在不同显示器。
headless
Supervisor 持有输入权
显示 TUI →
← 转为无头
headed
系统终端附着原 session
关闭终端窗口不等于停止任务。TUI Ctrl+C 或 Wails“取消当前 turn”才会发送 ACP cancel。
04

输入所有权与多客户端回退

输入来源

Supervisor prompt
Codex follow-up
TUI user input

Per-session FIFO

同一 session 仅允许一个 active prompt；busy 时所有新输入排队。

Grok session

切换显示形态时队列不丢失，cancel 只影响 active prompt。

优先：实时双端附着

ACP 执行过程中，TUI 同时附着并实时显示；TUI 输入进入同一 FIFO。

固定回退：安全边界交接

若当前 Grok 版本不稳定，则等待 turn 边界后把输入权交给 TUI；关闭 TUI 后再 session/load 恢复 Supervisor。

无论采用哪条路径，都不得创建替代 session，也不得重复已完成的工具调用。
05

任务与显示状态机

created→ starting→ planning→ plan_ready→ approve → executing→ completed
needs_input唤醒 Codex 和托盘提醒。
disconnected进入 recovering，恢复原 session。
cancelled保留 session，禁止自动继续。
blocked / failed返回短摘要与真实失败原因。
headless→ attaching→ headed→ detaching→ headless

业务状态和显示状态必须分开存储；首屏使用阶段而不是无法证明的百分比。

多轮任务协议

Turn 1调查与 Plan
Turn 2实施
Turn 3测试与修复
Turn 4Codex 验收返工
Turn N最终完成
prompt_complete 只表示当前 turn 结束，不表示逻辑任务完成。
<GROK_TASK_STATE>
{"state":"working|needs_input|completed|blocked","summary":"...","next":"..."}
</GROK_TASK_STATE>
状态Supervisor 行为
working自动向同一 session 发送继续。
needs_input暂停自动推进，唤醒 Codex，并通知 Wails。
completed返回完成摘要，让 Codex 做最终验收。
blocked返回具体阻塞条件，不用“继续”盲目重试。
缺少标记请求一次状态修复；再次缺少则转 needs_input。
07

Plan 审批流程

grok_dispatch创建持久 session，注入 cwd 与任务契约，开启 Plan。
Grok 调查读取项目并写入 session 目录中的 plan.md。
plan_readyexit_plan_mode 停在审批边界，返回短计划给 Codex。
Codex 决策approve、revise 或 cancel；通过后继续原 session。
08

MCP 控制面

grok_dispatch
批量创建任务，默认 headless，返回 job 与 session 映射。
grok_wait
等待 any / all 任务到达关键边界；不返回过程输出。
grok_plan_decide
批准、退回或取消 Plan，并可附带修改意见。
grok_followup
向同一 session 追加返工、继续或新的验收意见。
grok_cancel_turn
取消当前 turn，保留 session 和排队状态。
grok_set_view
在 headless 与 headed 之间切换，不重建任务。
grok_status
返回阶段、显示状态、摘要和最近边界事件。
grok_open_terminal
打开单任务 TUI 或集中 Grok Dashboard。
[mcp_servers.grok_supervisor]
command = "/path/to/GrokMcp"
args = ["mcp"]
startup_timeout_sec = 30
tool_timeout_sec = 21600
grok_wait：长时间阻塞，不轮询 Codex，不返回思考流、工具日志或完整 diff；只返回 plan_ready、needs_input、completed、blocked、failed、disconnected、cancelled。

12

断连恢复与用户取消

断连恢复

检测连接丢失 → disconnected → 重连唯一 Leader → session/load → 恢复 Plan → 检查工作树后继续。

十分钟内连续恢复失败两次，转 needs_input。

用户取消

Wails「取消当前 turn」→ ACP cancel → 当前 turn 停止 → session 保留 → needs_input，允许手动继续。任务级取消（PlanCancel）进入 cancelled，禁止自动恢复。

UserCancelled 的任务不得自动恢复。

16

验收清单

  • 新任务默认无头，且不会自动打开终端。
  • 显示 TUI 后附着原 session，不创建替代会话。
  • 关闭 TUI 后任务继续，状态切回 headless。
  • 切换过程不丢输入、不重复执行工具调用。
  • Wails 可以取消无头 turn。
  • TUI Ctrl+C 不会触发自动继续。
  • 同一 job 支持多个 Grok turn。
  • 多个 TUI 可同时放到不同显示器。
  • Wails 首屏显示全部任务阶段和最近动作。
  • Codex 等待期间不接收过程日志。
  • Plan 必须经过 Codex 审批。
  • 断连后恢复原 session。
  • Wails 重启后恢复任务清单。
  • Grok 缺失、未登录或版本不兼容时给出诊断。
  • macOS Intel、Apple Silicon、Windows x64 构建通过。
  • 默认共享 Codex 当前目录；worktree 仅由任务显式选择。
